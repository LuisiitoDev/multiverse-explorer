# 05 · Estado, evidencia y mejora

Estado inicial: PENDIENTE. Fuente: clases 5.1–5.8 del curso GH600.

Dominios relacionados: D3 10–15%; D4 15–20%. Son pesos completos de dominio, no de este laboratorio.

## Pasos

1. Completa checkpoint.json con un commit real, decisiones, pasos completados y pendientes.
2. Reanuda en una sesión nueva usando el checkpoint; comprueba diferencias desde la versión registrada.
3. Introduce un cambio controlado que vuelva obsoleta una referencia y decide qué evidencia repetir.
4. Ejecuta los tests relevantes y build del frontend; si tocaste backend, sus checks pertinentes. Registra comandos y resultados reales.
5. Clasifica un fallo: razonamiento, herramienta, contexto o entorno. Cambia una instrucción o restricción y compara resultados.

## Evidencia mínima

- Checkpoint y reporte de reanudación sin pasos duplicados.
- Evaluación antes/después con pruebas y versión.
- Diagnóstico de causa raíz y limitaciones.

## Comprueba comprensión

El build anterior pasó, pero el commit cambió después. ¿Puedes usar ese PASS para aceptar el cambio actual?

## Cierre

Registra qué ejecutaste, sobre qué commit y con qué resultado. Explica los bloqueos y lo que no se ejecutó. Actualiza coverage.csv; no marques una clase completada solo por haber leído este enunciado.
